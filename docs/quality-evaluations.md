# 质量评测：M1–M5

质量评测作为数据集的一项功能，在「评测数据集 → 数据集详情 → 评测记录」中运行，不改变现有性能日志不保存响应正文的行为。DeepEval 4.3.2、RAGAS 0.4.3 均调用官方评分 SDK。RAGAS 兼容生成与官方 `TestsetGenerator` 是两个明确区分的选项。

## 两种评测与数据集用途

在「评测数据集 → 数据集详情 → 评测记录 → 发起评测」中自动使用当前数据集，按数据集用途选择类型。运行列表可按类型筛选，详情、冻结配置与导出保留类型。

| 类型 | 被测对象 | 默认评分 | 数据要求 |
| --- | --- | --- | --- |
| RAG 评测 | LLM、Dify Chat | DeepEval 回答相关性与参考答案正确性，或 RAGAS 事实正确性 | 问题；所选指标需要时提供参考答案或应用实际召回 |
| 检索评测 | Dify 知识库 | DeepEval / RAGAS 上下文精确率与召回率；规则引擎使用 Recall@K、MRR、nDCG | 问题与参考答案（模型评分）；相关片段 ID / 分级相关性（排序规则），以及实际检索结果 |

检索评测只允许无需实际回答的指标，不提供答案生成或多轮设置。Dify 检索数量与排序指标 K 使用同一设置。规则指标无需评审模型；上下文评分需要独立评审模型。片段 ID 必须与检索服务实际返回的 ID 对齐。缺少标注或实际召回显示不可计算，空召回沿用原有评分规则。

「评测数据集」按用途分为 RAG 评测、检索评测、两者通用。创建、导入、生成与编辑支持设置用途，列表可筛选。发起评测固定使用当前数据集，仅允许与其用途兼容的类型；后端也按冻结版本的用途校验。用途不自动补齐答案和标注，修改用途不改写原有样本或冻结版本。历史数据集缺少用途时按两者通用读取，无批量数据改写；旧知识库召回运行显示为检索评测，历史未评分的记录仍保留原状。

## 快速开始

打开「评测数据集 → 数据集详情 → 评测记录 → 发起评测」，确认评测类型和被测对象，当前数据集自动带入，确认推荐指标与评审模型，点击「开始试跑」。默认最多运行 5 条，自动命名并保存数据快照，无需预先发布版本。

- 「对照参考答案」默认使用 DeepEval 回答相关性 + 参考答案正确性，或空间默认 RAGAS 的事实正确性。
- 「不使用参考答案」可用 DeepEval 回答相关性。当前 RAGAS 无参考指标需要应用返回实际召回，直接测 LLM 时会提示改用参考答案或切换 DeepEval。
- 「检索评测」默认对召回进行评分；选择确定性规则时不需要评审模型。旧 API 的 `retrieve_only` 采集模式保留兼容，新界面不再使用该模式。
- 评审模型沿用空间默认结果评分模型；未配置或已不可用时需要显式选择，不自动以被测模型代替。
- 运行范围支持 5 条、20 条、全部及自定义条数，均受预算限制。

DeepEval / RAGAS / 规则引擎、自定义指标、通过阈值、系统提示词及预算保留在「高级设置」。所需参考答案或实际召回会在所选指标下说明，缺少数据时仍按原规则标为不可计算，不生成虚假分数。评测开始时自动保存当前数据集快照，用于复现和历史对比。

## 完整操作流程

1. 在数据集中添加、导入或生成样本。参考答案和参考资料与应用实际回答、实际召回分别保存。
2. 在数据集的「评测记录」中选择被测对象，确认推荐指标与独立评审模型，先试跑 5 条。系统会自动保存当前数据集快照，不需要手动发布版本。
3. 查看逐条参考答案、实际回答、参考资料、实际召回、评分理由、缺字段、错误、耗时；支持 JSON、JSONL、CSV 导出。

评测只使用当前数据集中的启用单轮样本。历史运行保留创建时自动保存的快照。

## 查看本次评测结果

评测列表支持按名称或 ID 搜索，以及按类型、运行状态筛选。名称下方显示简短运行 ID，便于区分重名评测。

详情分为「评测结果」「对比分析」「运行配置」三个页签：

- 评测结果：顶部按指标展示平均分、通过率、有效评分 / 总样本、冻结阈值和分数分布。分布使用五个区间，最后一个区间包含满分 1；无有效评分时不绘制分布。完整统计及指标 ID 可在「指标统计详情」展开查看。
- 评测结果中的样本明细：每行一个问题，每列一个指标，直接展示得分和是否通过。支持问题搜索、失败/不可计算筛选，以及按单项指标低分或高分优先排序。未评分结果始终排在已评分结果后面。点击问题打开右侧详情，查看各指标得分、评分理由、参考答案、实际召回与运行证据；可连续查看上一条/下一条。SDK 返回的结构化评分理由按文字列表展示，原始 JSON 可在「原始评分信息」展开查看。
- 对比分析：选择历史运行进行逐条对比，查看同一批样本的指标变化。
- 运行配置：查看执行计数、请求/Token 用量、成本状态和冻结配置版本。

平均分只统计已完成的有效分数；通过率为达到该指标阈值的样本数除以有效评分样本数。缺少数据、评分失败、等待和取消的结果不记为零分，也不参与平均分或通过率；各指标独立展示，不合成为总分。汇总和分布始终来自本次运行的全部样本，不受下方搜索、排序或结果筛选影响。没有有效评分时显示「—」；真实零分仍显示为 `0.000`。计算口径通过标题旁的提示图标查看。

该界面直接使用保存的评测结果，已有评测无需重新运行模型。运行中的评测沿用原有轮询更新。

## 删除评测记录

空间所有者和管理员可在列表右侧或评测详情中删除记录。确认后清理本次运行、样本执行结果和指标得分；保留原数据集、冻结数据版本、其他评测和空间评分缓存。排队中或执行中的评测需先取消，已准备但未排队的记录可直接删除。删除不可撤销。

API：`DELETE /api/evaluation-runs/{run_id}`，成功返回 `{"deleted": true}`，活动任务返回 409，不存在的记录返回 404，无管理权限返回 403。

## 模板、指标与预算

| 类别 | 可用指标 | 数据要求 |
| --- | --- | --- |
| DeepEval 问答 | Answer Relevancy、Faithfulness、参考答案语义正确性 GEval | 实际回答；忠实度需实际召回；正确性需参考答案 |
| DeepEval 检索 | Contextual Precision / Recall | 问题、参考答案、实际召回 |
| RAGAS | Faithfulness、Context Recall、Context Precision 有/无参考变体、Factual Correctness | 每种变体在界面中声明依赖 |
| 排序规则 | Recall@K、MRR、nDCG | 人工标注相关片段稳定 ID / 0–3 相关性等级，以及实际返回 ID 顺序 |
| 业务规则 | 自定义 GEval rubric/示例、必需短语、JSON Schema | 规则随运行冻结 |

空召回在 ID 排序指标中为 0；未返回片段 ID 为缺数据。空实际召回无法为忠实度提供依据，显示缺数据。nDCG 理想增益为 0 时约定得分 0。

不同引擎/指标分别汇总，不能把同名分数混合平均。A/B 只在样本、完整指标规则/阈值、实现版本与裁判配置相同时显示可比较的分数差异；不同配置仍可查看各自结果，返回不兼容。

每次外部请求先原子预留请求数和最大输出 token。应用/裁判分别统计实际供应商用量；失败尝试仍计入预算，重试不重置预算。预算是输出额度预留而非计费上限；Dify 的实际输出上限由目标服务配置，必须与预留额度保持一致。价格未知时始终显示未知。认证/额度/无效请求停止整批无效调用，临时错误按有界退避重试。取消阻止后续提交，已发出的外部请求可能无法撤回。

成功评分可按空间缓存。内容、回答、召回、目标配置、裁判、规则或实现变化均使缓存失效；只缓存成功结果。

评分调用复用结构化生成的模型能力配置：仅对明确支持关闭思考的供应商和模型 UID 发送相应参数，避免评分 JSON 生成前消耗大量思考输出。新评测的 `result_judge.inference_parameters` 冻结实际参数，输出上限同时受评测预算与模型能力限制；每项评分的用量记录保留实际参数，评分缓存也包含这些参数。部署前已开始的评测保留已提交结果，未完成部分使用同样的结构化评分策略，并在评分用量中记录参数。样本表格的耗时是目标调用（检索评测中为召回与重排）的耗时，不包含评分模型的多阶段调用；DeepEval 的精确率、召回率通常各需要多个模型请求，样本和指标按顺序执行。

## 原生生成

官方 RAGAS 需要生成 LLM 和 embedding 模型、来源文档，支持官方图变换、单跳/多跳查询分布、Persona。整个图生成每次构建只尝试一轮，不在后台无限重新生成。SDK 输出不足时构建标为未完成，可显式续建；重新构建失败保留原有数据。来源参考不能精确映射回原始片段时标明 `unmapped`，不编造来源 ID。兼容模式仍可用于原来的无资料任务/种子扩写。

评测构建不提供人工审核、版本发布、覆盖率配额、语义去重或复杂场景管理入口。检索排序指标使用数据样本中已有的片段标注；评测快照只读保存，供运行复现。

评测接口沿用现有部署的认证方式。启用应用登录时，需要浏览器会话、空间权限及写操作的 CSRF 校验。

线上实际回答只保存为失败证据，不升级为标准答案。

## 持久队列与独立 worker

评测任务在 PostgreSQL 中排队，默认 API 内运行 2 个任务。每个运行由单一 worker 顺序处理样本；通过多个进程并行处理不同运行。`FOR UPDATE SKIP LOCKED` 领取、60 秒租约、10 秒续租、令牌 fencing、原子预算限制保证竞争与恢复。

```bash
# API 容器：设 EVALUATION_EMBEDDED_WORKER=false 后启动原来的单 API worker。
# 独立评测 worker：使用与 API 相同的 DATABASE_URL、认证配置和持久卷加密密钥。
python -m cli.evaluation_worker --concurrency 4
```

API 负责迁移数据库。独立评测 worker 不执行性能任务恢复或数据库迁移，启动不会将 API 正在运行的性能测试、构建或报告标为失败。不要增加 API 的 uvicorn workers；原性能调度仍由单 API 进程拥有。

worker 崩溃后租约到期重新领取，保留已提交回答/评分，只补未完成部分。旧令牌不能再次提交。外部 HTTP/模型调用为至少一次，崩溃发生在外部成功而本地提交前可能再次调用、计费；本地证据提交和预算持久化具备幂等保护。当前不是单个大任务内部的样本分片调度，也不承诺无限数据规模。

## 验证边界

自动化使用隔离 PostgreSQL、固定模型响应和真实 SDK 指标执行，覆盖质量链路、空间与凭据、预算、租约、恢复、独立 worker 及现有性能/认证回归。原生生成测试验证官方生成器的调用边界、分布和来源适配，不代表已对生产模型执行收费的完整图生成。实际模型输出质量、业务阈值和原生多跳来源适配仍应使用各自真实资料先做少量试跑。

## 空间默认配置

空间设置按用途分为「数据集生成」「质量评测」「AI 测试报告」三个页签。各页分别保存，切换页签保留未保存的编辑；离开空间设置页面后未保存的编辑不保留。提示词默认折叠，可展开编辑并逐项恢复默认，恢复操作需保存后生效。

数据集生成质量评审模型仅用于 DeepEval 构建时的初始问题检查；质量评测的结果评分模型用于给实际回答和检索结果评分，两者分别配置。

## 比较两次评测

在「对比分析」中选择一次已结束的同类型历史评测，页面自动读取已保存结果，不重新调用模型。选择项显示名称、时间、状态和短 ID，便于区分同名记录。评测快照必须相同；评分指标（包括规则与阈值）、评分模型与提示词、样本范围也需一致，才会判断提高或下降。不一致时说明原因，只展示原始分数。

先查看各指标的历史均分、本次均分、变化和可比较样本数。均分使用双方均评分成功的相同样本对，失败、缺失和未评分不计为零；不同指标可比较的样本数可能不同。差值为本次减去历史，按三位小数显示；四舍五入为零显示「基本不变」。这里没有把不同指标合成一个总分。应用 P95 耗时单独显示，越短越快，不包含评分耗时。

展开「查看逐题得分变化」可查看每题每个指标的分数，下降项排在前面，可筛选变化或搜索问题。切换结果与对比页签保留当前参照项；切换历史评测立即清空旧结果，避免混淆。

## 数据集内的评测记录

数据集详情包含「样本」「评测记录」「设置」。评测记录只展示当前数据集的运行，可筛选类型与状态，查看指标得分、逐样本结果、冻结配置、导出、历史对比和按权限删除。发起时自动固定当前数据集；检索用途默认检索评测，RAG 用途默认 RAG 评测，通用用途可选两种。空数据集及构建中的数据集需先准备好样本。

每次评测保存独立记录与不可变数据版本，后续编辑数据集不会改写历史结果。已有评测通过冻结版本自动归属，不需要迁移或重跑；后端先按数据集过滤再返回最近 100 条。主导航不再显示独立的质量评测入口，旧 `#evaluations` 链接仍可查看历史记录，新建操作引导回数据集。

## 多知识库召回与统一重排

检索评测可选择最多 20 个 Dify 知识库。默认勾选当前数据集关联且仍可用的知识库，也可手动增删。选择多个知识库时必须配置重排模型；空间设置 → 质量评测中可保存默认 Reranker，新建评测时默认选中，也可为本次评测更换。该模型通过模型供应商中已有的 Reranker 端点和凭据调用，不使用结果评分 LLM。

每库召回数量为每路的候选上限（1–100），最终 Top K 为合并后保留的结果上限（1–100），每库召回数量不能小于最终 Top K。各库保留其在 Dify 中配置的检索方式；候选阶段关闭 Dify 的分数阈值筛选，合并后由统一重排模型评分。分数阈值范围为 0–1，仅保留重排分数不低于阈值的结果，再取最终 Top K。单库未选择重排模型时使用原召回分数。筛选结果可以不足 K 条或为空，空召回不会被伪造为命中。

每条样本最多并行请求 4 个知识库，按知识库与真实片段 ID 去重；没有 ID 的片段仅按同库的相同文本去重，不伪造 ID。任一路失败不会将部分结果用于评分。请求预算涵盖知识库配置读取、每路检索、重排和评分；重排单独记录调用用量。取消、失败重试与工作进程租约仍适用。

vLLM 重排请求设置 `truncate_prompt_tokens: -1`，由服务端 tokenizer 按模型实际输入上限截断重排输入，避免单个长片段导致整批请求失败。完整召回原文仍用于后续评测并保留在样本证据中；“召回来源与运行信息”的 `retrieval_strategy.reranker_parameters` 记录实际截断参数。其他供应商不发送此 vLLM 专用参数；若服务拒绝超长输入或其他请求参数，界面显示对应的重排错误，不会使用部分结果评分。

评测快照冻结全部知识库、重排模型、每库召回数量、最终 Top K 和分数阈值。运行配置中显示策略摘要，样本的“召回来源与运行信息”保留最终片段所属知识库、原召回分数和重排分数。后续修改空间默认值不改变已有快照，执行前会检查每一路和重排模型是否与快照一致。旧版单库评测继续沿用原检索配置。
