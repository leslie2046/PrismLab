# Dify 知识库与聊天应用配置

在「Dify 配置」点击「新增 Dify 配置」，默认通过列表添加知识库：

1. 填写 Dify Base URL 和 Dataset API Key。Base URL 可使用实例根地址或以 `/v1` 结尾的 API 地址。
2. 点击「获取知识库列表」，只读取该密钥有权限访问的知识库。获取和选择不会保存配置，也不会修改 Dify 内容。
3. 按名称或 ID 搜索，勾选所需知识库，点击「添加所选知识库」。每个知识库按其名称和 ID 保存为独立的知识库检索配置，可用于测试计划、Playground、数据集构建及同步 Dify 资料。

列表每次加载最多 100 个知识库，有后续页时提供「加载更多知识库」。加载更多保留已有勾选；搜索不会清除其他结果的勾选。「选择当前搜索结果」复选框仅影响已加载且匹配当前搜索的记录，再次取消勾选可清除这些选择。同一 Base URL 下已配置的知识库标记为「已添加」，不能重复勾选。更改 Base URL 或密钥会清空获取结果和选择，需重新获取。

保存前沿用现有的连接与认证探测，API Key 加密保存。多个知识库逐项添加，显示进度；部分失败时保留已成功配置，失败项仍勾选，重试仅添加未成功项。关闭窗口或切换空间后停止提交后续项。

也可切换到「手动添加」，填写知识库 ID 和配置名称；名称旁的刷新按钮可获取对应知识库的名称。手动添加保留现有的环境密钥回退规则。同一服务下已添加的知识库应通过编辑入口维护。

已有配置通过「编辑」维护名称、Base URL、知识库 ID 与密钥；密钥留空表示保留原密钥，更换服务地址后需提供新密钥。选择「聊天应用」继续使用 Chat API Key，可获取已发布应用的名称。

配置按空间隔离，仅空间所有者和管理员可以获取列表、添加或编辑；普通成员可使用已配置的服务。沿用 `POST /api/dify/names` 的分页读取和 `POST/PUT /api/service-configs` 的加密保存接口，无数据库迁移。

## 聊天应用

选择「聊天应用」后，直接填写 Base URL、该应用的 Chat API Key 和配置名称，点击「保存」添加。名称旁的刷新按钮可通过 `/v1/info` 获取该密钥对应的应用名称。Chat API Key 仅能访问单个应用，无法获取整个应用列表；不再提供应用列表添加、控制台地址或控制台访问令牌功能。

通过应用名称获取接口返回的 `mode` 明确为 Workflow 时拒绝使用，Chatflow 可正常获取名称。保存及编辑继续沿用连接校验、密钥加密和同服务密钥复用规则。以前添加的应用配置仍可使用和编辑，其历史应用 ID 作为兼容元数据保留；更换密钥或服务地址后清除旧应用关联。知识库列表添加不受影响。
